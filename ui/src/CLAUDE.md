# ui/src/ — React UI (map, not a manual)

Mirrors the backend. Vite + React + Zustand + ReactFlow (`@xyflow/react`).

**Pixel look (2026-07-15):** the whole app lives in the office's world — theme tokens
are DERIVED FROM THE DIORAMA PALETTE (`officeArt.ts` hexes; dark = office after hours,
light = office by day), all type is pixel-family (Silkscreen display via
`px-display`/`px-brand`, Pixelify Sans body, VT323 mono — all @fontsource, imported in
`main.tsx`), square corners + hard-offset shadows via the `borderRadius`/`boxShadow`
scale OVERRIDES in `tailwind.config.ts`. Backgrounds stay simple (subtle tile, never
imagery). Theme tokens are scoped `html.light` (ReactFlow's own colorMode class would
hijack a bare `.light`). There is NO Simple/Technical mode — one adaptive UI, raw JSON
behind the detail panel's expander. Rules in the `vapviz-design` skill.

- `store/runStore.ts` — Zustand store; the pure `applyEventToGraph` + `totalLlmCost` re-implement the backend's reduction (the store's `applyEvent` just calls them). `selectRun(runId, tab?)` takes an optional landing tab (stored as `entryTab`; Building room clicks pass `"theater"`, default `"story"`).
- `lib/runControl.ts` + `components/RunControlBar.tsx` — Pause/Resume/Stop **+ Layer 2 message inject** for a live in-process run (Theater tab): the pure `controlUiState(desired, acked, runStatus, waitingForInput?)` table (unit-tested; adds the "waiting for your input" banner + `awaitingInput` flag) + a bar that polls `GET /runs/{id}/control` ~1s, POSTs actions, and POSTs a message to `/runs/{id}/input` (text box + Send). **UI-only — NOT dual-logic** (the `stopped` status + `control` event type ARE; see the sharp edge below).
- `hooks/useOfficeControl.ts` + `components/OfficeStage.tsx` `control` prop — the Theater office "rests" (CSS dim/desaturate + a `.vt-office-rest` badge) while the run is paused (`acked==="paused"`) or waiting for input. Hook polls `/control`; the sprite renderer + locked art are untouched. **UI-only.**
- `hooks/useRunStream.ts` — one `EventSource` per selected run; `RunList` polls `/runs` ~3s.
- `components/RunList.tsx` — **app-grouped sidebar**: groups runs into apps via `lib/building.ts`'s `appKey`/`groupApps` (key = `app_id ?? label`); expand an app → run-history rows (select → inspect/replay).
- `components/AgentGraph.tsx` — dagre layout + ReactFlow; node color = kind (`KIND_BG`), border = status.
- `types/events.ts` — TS mirror of `vapviz/events.py`.
- `lib/theater.ts`, `lib/sprites.ts` + `lib/officeArt.ts` + `lib/officeScene.ts` + `OfficeStage.tsx` (the sprite office — full-size in the Theater tab, `compact` in the Building's rooms; desks assigned by sorted agent name so seats stay stable; art rules in the `pixel-art-set` skill, provenance in `lib/ASSETS.md`) — **UI-only presentation** of the already-derived graph.
- `lib/building.ts` + `components/BuildingView.tsx` — the Office Building monitor (`view:"floor"`): pure `buildBuilding(runs, prev, dismissed)` placement (stay put → failures stay red + surface to `Building.lounge` → seat new → descend cascade; 6 rooms/floor), polled `/runs`+`/graph`, dismiss persistence in `localStorage["vapviz.dismissed"]` (pruned on load). **Visual building (4b):** CSS shell (roof/slabs/lobby directory board), 2×3 rooms around a Walk Way, Door/Stairs column; `lib/loungeArt.ts` + `LoungeStage.tsx` (break-room diorama, per-agent idle activities); `lib/walkOverlay.ts` (sprite layer above the rooms — descent walks Walk Way→Stairs *vanish*→Door below, failures walk to the lounge; FLIP is the fallback, reduced-motion snaps). **Floor life (4c, honest-only since 4d):** the same overlay also runs a persistent layer (`reconcileFloorLife`, called each poll) — one honest walker per *running* room mills on its floor's Walk Way (out a `.vt-room-door` anchor on the room's corridor edge); no floor life under reduced-motion. **Floor environment (4d):** `lib/floorArt.ts` + `components/FloorEnv.tsx` — a per-floor canvas under the rooms draws the whole floor as one pixel scene from measured DOM rects (corridor stone, shared wall runs + door thresholds, runner rug + ceiling lights, plants/cooler/notice board/wall art/clock, Door/Stairs alcove icons, east-wall windows); rooms lost their CSS card chrome and gained wall-signage nameplates (`.vt-plate`, DOM text + status LED, fixed diorama palette); the 4c ambient stroller was **deleted** — an idle floor is an empty corridor. **Floor-room control (agent-control L2 ride-along):** a running room's tile exposes hover-revealed Pause/Resume/Stop icon buttons (`RoomTile`; reuses `controlUiState`); the poll fetches each running room's `/control` latch and POSTs actions optimistically. Message-inject stays Theater-only.

## Sharp edge — DUAL LOGIC (must stay in sync)
`applyEventToGraph` / `totalLlmCost` (runStore.ts), `types/events.ts`, and the cost reduce here MUST track their Python counterparts in `vapviz/` (`_apply_event_to_graph`, `events.py`, `_total_cost`) — guarded by the cross-impl parity test (`runStore.parity.test.ts` ↔ `tests/test_reducer_parity.py`, shared fixtures in `tests/fixtures/reducer_parity/`). See `vapviz/CLAUDE.md`. **`lib/replay.ts` (`buildGraphAt`) is a THIRD copy of the reduction** (nodes+edges only, for the replay scrubber) — the parity test replays the fixtures through it too. **`hooks/useRunStream.ts` must listen for every `EventType`** (SSE named events drop silently otherwise) — its list is `satisfies Record<EventType, …>` so tsc enforces it. **In scope from the control channel:** the `stopped` `NodeStatus` (reducer ternary mirrors Python's `_terminal_status`: error > stopped > success) and the inert `control` `EventType` — fixtures `stopped_run.json` / `control_inert.json` / `control_input_inert.json` (the last: a Layer 2 `action="input"` message audit, ignored identically by both reducers). Layer 2 added **no** new event type. A new `NodeStatus` also touches every `Record<NodeStatus,…>` map (StatusBadge, BuildingView `DOT`, AgentGraph, `cssColor.ts` + the `--status-stopped` token). **Exempt:** `lib/theater.ts` / `lib/sprites.ts` / `lib/officeArt.ts` / `lib/officeScene.ts` / `lib/building.ts` / `OfficeStage` / Theater + Building views only re-present derived data, so they are *not* part of the dual-logic rule. (`app_id` is likewise outside it: set at run creation from `agent_start` data, never touched by the reducers. The control *latch* + mailbox UI — `lib/runControl.ts`, `RunControlBar.tsx`, `hooks/useOfficeControl.ts`, the `OfficeStage` `control` prop, and the floor-room controls in `BuildingView.tsx` — is outside it too.)
